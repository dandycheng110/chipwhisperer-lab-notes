側信道分析

晶片運算時,耗電量會隨處理的資料細微變化。就像隔著門聽人打字、從節奏猜出內容——我們量 AES 運算的功耗波形,反推金鑰,全程不碰金鑰本身。

02 Lab · SCA101 側信道分析

只靠功耗波形,還原整把 AES 金鑰

用的是 CPA(相關性功耗分析)。AES 第一步會算 Sbox[明文 ⊕ 金鑰];對每個位元組,把 0~255 的金鑰猜測全試一遍,用「這個中間值有幾個 bit 是 1」當作預測耗電量,再跟實際波形算相關係數。猜對的金鑰,相關係數會明顯高過其他 255 個。

03 Lab · Fault101 故障注入

一個壞時脈邊緣,讓迴圈算錯

target 跑一個 50×50 的迴圈,cnt 正常應該 = 2500。在迴圈執行時對時脈灌一個超短的壞邊緣(clock glitch),CPU 就可能跳過一次 cnt++,甚至整個算爆。我們掃 2645 組 (width, offset, ext_offset) 參數,找出有效的毛刺。

五次成功中最漂亮的一筆是 cnt = 2499——剛好少數一次 cnt++,是教科書級的「單一指令跳過」。另外幾筆把回傳值整個打亂成天文數字。

04 Lab · 進階故障注入

一個毛刺,繞過密碼驗證

韌體的 'p' 指令比對密碼(正解 "touch"),passok 預設為 1,只在比對到不符時設成 0。攻擊時送一組錯的密碼,正常會被拒絕;但在比對迴圈執行時下毛刺,讓「設為 0」那一步被跳過,passok 就保持 1 —— 錯的密碼被判定為通過。這正是繞過安全開機、跳過韌體簽章檢查的同一個原語。

05 Lab · SCA 方法二 · DPA

DPA:另一條路,也能還原金鑰

DPA(差分功耗分析)換個角度:靠「Sbox 輸出某個 bit 是 0 還是 1,平均功耗會差一點點」把波形分成兩群相減,正確金鑰會浮現最大峰值。它比 CPA 弱、需要更多波形——下表就是最好的證明。

波形數CPA 還原DPA 還原
10016 / 164 / 16
30016 / 1614 / 16
70016 / 1616 / 16
200016 / 1616 / 16

CPA 只要 100 條就破全金鑰;單 bit DPA 要約 700 條才追上。兩種方法最終都還原了完整 AES-128 金鑰——這也是為什麼實務上 CPA 是主流。

延伸 從桌上練習到無人機安全

你剛練的兩招,正是攻破無人機的兩把鑰匙

目標晶片是 STM32F303,而絕大多數開源飛控(Pixhawk、ArduPilot / PX4、Betaflight)用的是 STM32F4 / F7 / H7——同一個 ARM Cortex-M 家族。桌上做到的事,換一片飛控晶片幾乎照搬。

韌體萃取 · 繞過安全開機

飛控韌體常用 STM32 的讀取保護(RDP)上鎖。用電壓/時脈毛刺可在保護判斷的瞬間繞過——就是你剛做的「毛刺繞過密碼」的同一招,換成晶片內部的檢查。

圖傳 / 遙測金鑰側信道

加密圖傳、MAVLink 簽章、配對金鑰都要跑 AES/HMAC。量到那段功耗,CPA/DPA 就能挖出金鑰——跟桌上這次一模一樣。

CW-Lite 的 20-pin 連接埠能對外部目標輸出毛刺與量功耗,所以可以接一片真實的 STM32 飛控或 Nucleo 做實驗。完整研究路線(含 MAVLink 通訊安全與合規邊界)見 repo 的 無人機安全研究延伸.md。

筆記 踩坑實錄

三個卡住我最久的地方

1
Homebrew 的 arm-none-eabi-gcc 缺 newlib,編韌體會噴 stdint.h not found。官方 cask 是 .pkg 需 sudo,改用 brew fetch 下載、pkgutil --expand-full 免密碼解開當工具鏈。編韌體前把 ~/arm-gnu-toolchain/bin 擺 PATH 最前面。
2
macOS 用 system_profiler 讀 USB 常空白,改用 ioreg -p IOUSB -l 才看得到板子(NewAE VID 11070 / 0x2b3e)。
3
板子出廠韌體 0.50.0 與 chipwhisperer 6.0.0 不相容,用 scope.upgrade_firmware() 升到 0.65.0 才能正常讀寫設定。

附錄 如何重跑

環境與指令

環境都建在家目錄:~/cw-venv(Python 3.12 + chipwhisperer 6.0.0)、原始碼 ~/chipwhisperer、腳本與圖 ~/chipwhisperer-labs。

# 編韌體(以 AES 為例)
export PATH="$HOME/arm-gnu-toolchain/bin:$PATH"
cd ~/chipwhisperer/firmware/mcu/simpleserial-aes
make PLATFORM=CWLITEARM CRYPTO_TARGET=TINYAES128C

# 跑 lab 腳本
~/cw-venv/bin/python ~/chipwhisperer-labs/02_connection_test.py
~/cw-venv/bin/python ~/chipwhisperer-labs/04_sca101_cpa.py
~/cw-venv/bin/python ~/chipwhisperer-labs/05_fault101_glitch.py

# 開官方 Jupyter notebook
~/cw-venv/bin/jupyter lab --notebook-dir ~/chipwhisperer/jupyter
